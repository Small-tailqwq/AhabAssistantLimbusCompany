# AAALC 预发布

发布包必须与明确的源码提交、模式和发布说明对应。

## 权限与证据

- 检查原工作区与已有发布，保留无关改动；必要时在隔离 worktree 准备发布。
- 不打印或提交凭据。
- push、tag、Release 修改及远端重跑仅在已有授权内执行。缺少外部写入授权时，先准备可审阅的本地结果，再请求所缺授权。
- 不静默重定向已发布 tag；修复或撤回前核对消费者和当前远端状态。

## .NET 发布

先读 [构建说明](../../../docs/build.md)，再检查 `scripts/build_dotnet.py` 与目标提交的工作流。

1. 明确源提交、版本、模式和已验证功能，维护 `CHANGELOG.md` 与对应 Release body。
2. 执行受影响的构建、现有测试及本地打包；`full`、`fdd`、`trimmed` 的运行前提分别说明。
3. 核对 `artifacts/publish/<mode>/AAALC-<mode>.7z` 和解压目录；包含 `AAALC.exe`、`app/`、资源、OCR 模型和场景，RDP 宿主位于 `app/clone-host/`。
4. 仅在授权范围内实测发布包。构建成功不能代替桌面、OCR 与分身验证。
5. 外部发布前展示提交、tag、remote、文件清单与发布说明；只补充尚未授予的授权。
6. 发布后核对 tag 指向、prerelease 状态、附件内容及源提交，报告实际验证和缺口。

CI 执行构建与测试；发布附件由本地打包脚本生成。

## 完成

报告源提交、版本、实际产物、验证结果和已执行的外部操作；仅完成本地构建时明确说明。
