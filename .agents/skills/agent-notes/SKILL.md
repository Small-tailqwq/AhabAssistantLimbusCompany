# Agent Notes

写作前读[笔记契约](../../notes/README.md)。规则维护不扩大当前任务授权；未追踪资产、发布与删除仍按根 AGENTS 处理。`uv run python scripts/agent_notes.py check` 检查格式和封存，作者负责真实性、必要性及决策归属。

## 1. 判断是否需要笔记

同时满足以下条件才写：存在真实的长期选择，或需要说明某项能力为何被刻意排除；后续贡献者可能误改或重新推导；代码、测试、注释和当前文档未承载理由。

机械编辑、局部 UI 调整、原因清晰的小缺陷、无策略选择的依赖升级跳过。多个代理围绕同一决定协作时，共用一条笔记，避免按会话重复记录。

## 2. 查归属与取代关系

按主题和机制搜索 proposed、implemented、rejected 活跃目录，不只按文件名搜索。

- 同一决定已有归属：更新事实，不新建重复笔记。
- 新决定反转或缩小旧决定：新建并双向链接，同次判断旧记录存废。
- 完全吸收旧 implemented 记录：先按契约保留独有理由、替代方案、后果、必要验证与覆盖缺口，再修复入链并删除。部分取代继续保留两者。

## 3. 写作

1. 路径为 `{lifecycle}/{class}/yyyy-mm-dd-topic.md`，日期是首次提出日。已实施用 implemented，尚未完成的实质工作用 proposed。
2. 头部依次为 `# Agent Note: 标题`、空行、`Status:` 行、空行。
3. `## 问题` 独立解释动机；`## 决策` 或 `## 提案` 写明确的路径、机制、默认值、约束及失败行为。
4. `## 曾考虑的替代方案` 只写真正权衡过的选项与理由，不为填章节编造经历。旧笔记的豁免按契约处理。
5. `## 后果` 同时说明收益与代价；用相对链接引用具体源码和当前文档。
6. 运行 `uv run python scripts/agent_notes.py lint`（即[文风检查](references/prose.md)的检索，作用于改动的笔记），按对应检验逐条判断并修正不通过的命中；再通读笔记，检查检索找不到的含糊范围、无出处的断言和病句。既未改写也未说明理由的命中意味着笔记未完成。命令执行结果、本机版本、取代检索结果等会话事实放在对用户的报告里。

## 4. 生命周期变化

- proposed → implemented：提案改为当前决策，验收标准与风险归入后果或现有验证事实，文件日期不变。
- proposed → rejected：状态行写真实的一行理由，正文保持提案时内容。
- implemented 决策被反转：创建新笔记，不能就地写成相反决定。

## 5. 按价值退役

结合现有代码、配置、文档、其他笔记及入链判断，字数和日期只帮助定位。

- 小 UI 或纯机械记录可删除；局部修复、性能、能力、行为和所有权决定不能只因已完成就删除。
- 未来仍会用到的取舍、兼容语义、所有权、安全边界和重新引入条件保留活跃。
- 不再指导未来改动但有历史价值的已实施笔记归档。
- 提案不归档；不再推进则转 rejected。
- rejected 只在能阻止可能重现的错误时保留。

不按配额清理。边界案例报告依据；删除前满足合并与资产要求。

模板的校准例来自 deepseek-harness：折叠侧栏控件、仅重排 import 的模块迁移可删除；事件持久化边界、配置根所有权、仍约束调度的并行检查、明确重新引入条件的能力决定保留。被否决的合包方案若仍易误用则保留；依赖已消失协议的提案可以删除。这些例子只校准判断，不是本项目事实。

## 6. 归档已实施笔记

1. 先确认事实已满足归档条件；归档动作不顺带更新正文。
2. 笔记仍在 `implemented/<class>/` 时，在 `Status: implemented` 下一行插入 `Archived: YYYY-MM-DD`，双语时所有语言同时处理。
3. 双语时此刻运行 `uv run python scripts/agent_notes.py pair --write implemented/<class>/foo.md`：`pair --write` 只接受活跃路径，已封存的 sidecar 无法重新记录。
4. 将笔记及副本、sidecar 原样移到 `archived/<class>/`。
5. 活跃入链指向当前依据，确需历史引用的改指向归档；删除无用入链。
6. 运行 `uv run python scripts/agent_notes.py seal`、`uv run python scripts/agent_notes.py check`。清单只追加哈希，已封存记录保持冻结。

## 7. 双语

仅在 config 开启副本语言时执行。按差异最小更新副本，保持结构、代码块和机器标记一致，确认同义后运行 `uv run python scripts/agent_notes.py pair --write <路径>`，路径相对 notes 目录。`--all` 仅用于已授权的全量确认。

## 8. 验证与交付

运行 `uv run python scripts/agent_notes.py check`、`uv run python scripts/agent_notes.py lint`、项目要求的指引检查及针对改动的 `git diff --check`。检查新增或迁移的入链、相对路径和锚点。门禁不替代语义审阅，不验证归档出链。

报告实际新增、更新、迁移、归档或删除项（各附一行理由）、取代判断、修复的入链、每条 lint 命中及其保留或改写判定（保留的写明通过哪项检验）、边界判断和重要缺口；简单修改无需完整台账。检查通过且无具体未解决问题后交付，不为文档改动运行业务测试。
