# Agent Notes 文风检查

代理写的笔记会以可预见的方式出错：泄漏写作会话、用防御性限定包裹事实、把事实写得过松而无法核实。对每个可疑段落只用一个检验：**读者只看当前提交，看不到对话记录、PR 讨论或未提交草稿时，能否定位每个引用并核实每个事实？** 不能时，从仓库视角重述仍成立的事实，删除其余内容。段落仍承载事实时先重述事实，再删除。

## 需要移除的泄漏

1. **失效的会话引用：** `（决定 7）`、`（审计 C2）`、`方案 §4`、阶段标签、指向对话的“如上讨论”。改为按路径引用已提交的归属，或直接重述事实。
2. **变更与提交视角：** “本次改动”“这次接入”“后续 PR”“上一个提交”“以前”“不再”“现在”，以及 `this PR adds`、`no longer`。陈述当前机制；已修复的回归写成反事实：“缺少 X 时会出现 Y”。
3. **审阅过程：** “审阅中否决”“审阅者确认”“本笔记第三版”“维护者明确要求”“用户要求”。保留决定和理由，写成项目自身的规则；去掉谁在何时说过。
4. **写给审阅者的辩护：** 为赢得争论而写的“这样是安全的，因为……”。改为陈述使其安全的不变量。
5. **推导过程：** “先做 X，再做 Y”，逐步复述测试或显而易见的分支。只保留得到的契约。
6. **含糊与遗留：** “目前大概够用”“应该足够”、没有归属的推迟。改为带 issue 的 `TODO`，或写出实际界限。
7. **混杂的工作语言：** 用一种语言写成的正文里残留另一种语言的草稿片段。
8. **作者机器事实：** 写笔记那台机器的工具版本、操作系统或路径，例如“使用 Python 3.12.10 安装”“在本机 Windows 上测试”。读者在当前提交上无法核实。改为仓库实际强制的要求（配置文件中的最低版本、CI 矩阵），或删除。
9. **草稿历史：** “原 55 项”“旧锚点”“最初选择的”，以及 `the original 55 entries`、`legacy anchors`。这些描述未提交改动之前的状态，读者在提交上看不到。同一变更中落地的笔记之间的取代也属于这种泄漏：被取代的决定从未进入仓库。描述得到的布局及其稳定契约（“`patch-N` 锚点保持稳定以供引用”），把另一条笔记链接为相关而非取代。
10. **过程汇报：** “本笔记负责……”“没有需要取代的旧笔记”、作者检查过哪些内容的清单。这些是写作会话的报告，放在变更说明或给用户的汇报里。

## 不算泄漏

- 作为证据的 issue 与已合并 PR 引用（`#123`）。
- “缺少 X 时会出现 Y”的回归解释，以及实测界限（“实测：512 项约 0.15 秒”）。
- 运行时的新旧状态（“旧连接排空后新连接才接收请求”）。
- `## 曾考虑的替代方案` 章节本身，以及以“我们”表达的项目口吻。

## 读起来像机器写的句式

这些句式增加字数而不增加事实。每种都有检验；检验不通过才改写。

- **范围免责：** “X 不能证明／不保证／不代表／不等于 Y”。只有读者确实可能过度解读 X 时保留，例如可能被误当作带宽测量的延迟探针。前一句已经说明 X 检查什么时，删除免责句。
- **无端否定：** 笔记和仓库都没有暗示会这样做时写“不配置远端分支保护”。删除；如果缺席是有意的决定，把理由写成事实。
- **稻草人对比：** “不是 A，而是 B”“而非 A”。删掉 A 半句再读：只有读者或代理现在很可能去做 A 时才保留，例如针对代理确实会做的事的禁令。上下文已经点名的真实替代方案不算，直接写 B。
- **递进对子：** “不仅 A，更 B”“既 A，也 B”。只有在 A 的前提下 B 出人意料时保留，否则平列。
- **宣告重要性：** “值得注意的是”“关键在于”“本质上”。删除宣告；分句重要就放到句首或单独成句。
- **冒号揭晓：** “答案很简单：……”“原因只有一个：……”。直接陈述答案。
- **惯性三联：** 一两个就能承载事实时写了三个形容词或三个并列分句。只保留各自增加事实的项。
- **收尾总结：** 段末复述本段（“总之，……”“这样一来，……”）。除非段落长到读者需要结论重复，否则删除。
- **破折号与加粗密度：** 一段里多个破折号或加粗短语。改用断句或列表；加粗只留给改变行为的那一句。

## 写得过松、无法核实的事实

笔记的价值取决于读者能据以行动的事实。下列情况即使每个字都对，也通不过开头的检验。

- **含糊指代：** “相关理由”“必要时”“等等”，以及 `the relevant files`、`as needed`、`etc.`。检验：读者能否准确列出所指？写出文件、条件或条目；清单很长时链接拥有它的文件。
- **歧义范围：** “AGENTS 与 skill 各维护一份”（各一份副本，还是各一种语言？）。检验：句子能否有两种读法？写出你要的那种（“各自只保留当前语言”）。
- **无锚点的断言：** 没有路径、命令、配置键或来源的行为、默认值、上限或测量数字。检验：读者能否找到它在哪里被强制或测量？补上锚点，或删掉断言。
- **重复归属方的事实：** 复述已链接契约里的内容（“门禁会检测过期的章节哈希”）。删除句子，保留链接。
- **病句：** 用笔记自身语言重读每一句。混搭结构（“属于……之外”应为“不在……范围内”）、中途换主语、副本沿用另一种语言的语序都不合格。先修语法再判断其他问题；病句会掩盖它陈述的是哪个事实。

## 检索

检索结果是候选而非违规。用上面的检验逐条判断，改写不通过的，保留有理由的，并对每条命中报告保留或改写的判定。还要不借助模式通读信息最密集的段落：检索会漏掉未列出的表达，歧义范围、无锚点断言和病句也没有可靠的模式。

`python scripts/agent_notes.py lint` 对相对 `AGENT_NOTES_BASE_REF`（默认 `HEAD`）有改动或未追踪的每条活跃笔记运行这些检索，覆盖所有语言文件，并标出指向基线中不存在笔记的取代链接；`NOTE...` 或 `--all` 扩大范围，从不失败。config 设 `"proseLint": true` 时，`python scripts/agent_notes.py check` 通过后也会列出这些候选。其他文件手动运行（把 `FILES` 换成文件）。

```sh
# 范围免责与无端否定
rg -ni "(does not|doesn't|cannot|can't|won't) (prove|guarantee|mean|imply|ensure|verify|judge)|不能(证明|保证|判断|代表|说明)|不(意味着|代表|等于|保证)|并不|只(能)?说明|不配置|不提供|不涉及" FILES
# 稻草人对比与递进对子
rg -ni "not [^.]{1,40}, but|rather than|instead of|不是.*而是|而非|并非|不仅|既.*，也" FILES
# 宣告与收尾总结
rg -ni "worth noting|importantly|essentially|in short|值得注意|关键在于|本质上|总之|这样一来" FILES
# 会话视角、过程汇报与作者机器事实
rg -ni "(^|[^A-Za-z])this (PR|change|note|session)([^A-Za-z]|$)|本次|这次|此次|本笔记|维护者(的)?(明确)?要求|用户要求|locally|本机|(Python|Node|node|python) ?v?[0-9]+\.[0-9]+\.[0-9]+" FILES
# 草稿历史
rg -ni "originally|previously|formerly|no longer|used to|the old |legacy|[0-9]+ original|最初|原先|原本|原来|此前|曾经|不再|改为|原 ?[0-9]|旧 ?`" FILES
# 含糊指代
rg -ni "(^|[^A-Za-z])(etc\.|and so on|as needed|as appropriate|various|relevant (files|docs|code|parts|settings|rationale|changes))|相关(文件|文档|代码|配置|逻辑|内容|部分|理由)|相应的?(文件|文档|代码|配置|修改|处理)|某些|若干|一些|适当|必要时|等等|之类" FILES
```

## implemented 笔记的文风

- 用现在时描述已存在的东西；不写“应该”、迁移计划或验收清单。
- 每个事实只有一个归属：链接到代码、文档或其他笔记，不重复陈述。
- 用具体名称代替比喻：写出文件、函数、配置键或命令。
- 只强调改变行为的那一句。
