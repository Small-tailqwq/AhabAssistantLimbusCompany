# Agent Notes 文风检查

读者只看当前仓库时，应能定位引用并核实事实。修正不清楚的段落时先保留必要事实，再删除会话叙述。

- 会话编号、审计阶段、“如上讨论”改为可访问的文件或 issue 引用。
- “本次改动”“后来会”“维护者要求”“审阅者确认”改为项目当前机制；对真实替代方案的比较保留在专门章节。
- 工具运行记录、机器版本、取代检查结果放在交付报告，不放笔记。
- implemented 用现在时，迁移计划或未来工作写入对应提案。
- 每个事实只有一个归属，使用具体路径、函数、配置键和命令。
- “X 不代表 Y”只在读者可能误解时保留；去掉无依据的限制、夸大和重复结尾。
- “不是 A 而是 B”只在 A 是实际可能的误用时保留；直接说明 B 通常更清楚。
- Issue 或已合并 PR 可以作为证据；“缺少 X 会导致 Y”可解释必要不变量。

用 `rg -n` 对改动文件检索下列候选，逐条判断，不把匹配结果当作违规，也不为此新增门禁：

```text
不能(证明|保证|判断|代表)|不(意味着|代表|等于|保证)|并不
不是.*而是|而非|并非|不仅|既.*，也
值得注意|关键在于|本质上|总之|这样一来
本次|这次|此次|本笔记|维护者(的)?(明确)?要求|用户要求|本机
this (PR|change|note|session)|locally|worth noting|importantly|rather than
```

检索会漏掉其他表达，还需阅读信息最密集的段落。合理的实测边界和真实取舍保留，不追求机械清零。
