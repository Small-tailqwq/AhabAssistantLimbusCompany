# Agent Notes 文风检查

代理写的笔记会以可预见的方式出错。对每个可疑段落只用一个检验：**读者只看当前提交，看不到对话记录、PR 讨论或未提交草稿时，能否定位每个引用并核实每个事实？** 不能时，从仓库视角重述仍成立的事实，删除其余内容。段落仍承载事实时先重述事实，再删除。

## 需要移除的泄漏

1. **失效的会话引用：** `（决定 7）`、`（审计 C2）`、`方案 §4`、阶段标签、指向对话的“如上讨论”。改为按路径引用已提交的归属，或直接重述事实。
2. **变更与提交视角：** “本次改动”“这次接入”“后续 PR”“上一个提交”“以前”“不再”“现在”，以及 `this PR adds`、`no longer`。陈述当前机制；已修复的回归写成反事实：“缺少 X 时会出现 Y”。
3. **审阅过程：** “审阅中否决”“审阅者确认”“本笔记第三版”“维护者明确要求”“用户要求”。保留决定和理由，写成项目自身的规则；去掉谁在何时说过。
4. **写给审阅者的辩护：** 为赢得争论而写的“这样是安全的，因为……”。改为陈述使其安全的不变量。
5. **推导过程：** “先做 X，再做 Y”，逐步复述测试或显而易见的分支。只保留得到的契约。
6. **含糊与遗留：** “目前大概够用”“应该足够”、没有归属的推迟。改为带 issue 的 `TODO`，或写出实际界限。
7. **混杂的工作语言：** 用一种语言写成的正文里残留另一种语言的草稿片段。
8. **作者机器事实：** 写笔记那台机器的工具版本、操作系统或路径，例如“使用 Python 3.12.10 安装”“在本机 Windows 上测试”。读者在当前提交上无法核实。改为仓库实际强制的要求（配置文件中的最低版本、CI 矩阵），或删除。
9. **过程汇报：** “本笔记负责……”“没有需要取代的旧笔记”、作者检查过哪些内容的清单。这些是写作会话的报告，放在变更说明或给用户的汇报里。

## 不算泄漏

- 作为证据的 issue 与已合并 PR 引用（`#123`）。
- “缺少 X 时会出现 Y”的回归解释，以及实测界限（“实测：512 项约 0.15 秒”）。
- 运行时的新旧状态（“旧连接排空后新连接才接收请求”）。
- `## 曾考虑的替代方案` 章节本身，以及以“我们”表达的项目口吻。

## 读起来像机器写的句式

这些句式增加字数而不增加事实。每种都有检验；检验不通过才改写。

- **范围免责：** “X 不能证明／不保证／不代表／不等于 Y”。只有读者确实可能过度解读 X 时保留，例如可能被误当作带宽测量的延迟探针。前一句已经说明 X 检查什么时，删除免责句。
- **无端否定：** 笔记和仓库都没有暗示会这样做时写“不配置远端分支保护”。删除；如果缺席是有意的决定，把理由写成事实。
- **稻草人对比：** “不是 A，而是 B”“而非 A”。删掉 A 半句再读：只有读者或代理现在很可能去做 A 时才保留，例如针对代理确实会做的事的禁令。上下文已经点名的真实替代方案不算，直接写 B。
- **递进对子：** “不仅 A，更 B”“既 A，也 B”。只有在 A 的前提下 B 出人意料时保留，否则平列。
- **宣告重要性：** “值得注意的是”“关键在于”“本质上”。删除宣告；分句重要就放到句首或单独成句。
- **冒号揭晓：** “答案很简单：……”“原因只有一个：……”。直接陈述答案。
- **惯性三联：** 一两个就能承载事实时写了三个形容词或三个并列分句。只保留各自增加事实的项。
- **收尾总结：** 段末复述本段（“总之，……”“这样一来，……”）。除非段落长到读者需要结论重复，否则删除。
- **破折号与加粗密度：** 一段里多个破折号或加粗短语。改用断句或列表；加粗只留给改变行为的那一句。

## 检索

对改动文件运行以下检索（把 `FILES` 换成文件）。结果是候选而非违规：用上面的检验逐条判断，保留有理由的命中；检索会漏掉未列出的表达，还要不借助模式通读信息最密集的段落。不为此新增门禁。

```sh
# 范围免责与无端否定
rg -n "不能(证明|保证|判断|代表)|不(意味着|代表|等于|保证)|并不|不配置|不提供|不涉及|(does not|doesn't|cannot|can't|won't) (prove|guarantee|mean|imply|ensure|verify|judge)" FILES
# 稻草人对比与递进对子
rg -n "不是.*而是|而非|并非|不仅|既.*，也|not [^.]{1,40}, but|rather than|instead of" FILES
# 宣告与收尾总结
rg -n "值得注意|关键在于|本质上|总之|这样一来|worth noting|importantly|essentially|in short" FILES
# 会话视角、过程汇报与作者机器事实
rg -n "本次|这次|此次|本笔记|维护者(的)?(明确)?要求|用户要求|本机|this (PR|change|note|session)|locally|(Python|Node|node|python) ?v?[0-9]+\.[0-9]+\.[0-9]+" FILES
```

## implemented 笔记的文风

- 用现在时描述已存在的东西；不写“应该”、迁移计划或验收清单。
- 每个事实只有一个归属：链接到代码、文档或其他笔记，不重复陈述。
- 用具体名称代替比喻：写出文件、函数、配置键或命令。
- 只强调改变行为的那一句。
