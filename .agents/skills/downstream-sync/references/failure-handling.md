# 下游回流失败处理

| 情况 | 处置 |
|---|---|
| 本次回流产生的 cherry-pick 冲突 | 检查 base/upstream/downstream 行为，按已确定的移植范围逐文件解决；行为取舍不明确时先报告，绝不一刀切选一边 |
| 依赖缺失 | 在同一组中包含最小依赖，或改写为无依赖 |
| 验证失败 | 不提交；修复，或只中止进行中的应用 |
| 部分历史移植 | 区分已存在行为与缺失行为，只提交缺失的 delta |
| 原工作区脏 | 保持不动，保留已验证的 worktree 分支供后续集成 |

用户原有冲突以及 stash pop、merge 冲突保留现场；没有明确处置指令时不自行裁决。

被阻塞或部分回流用 `SKILL.md` 的最终报告结构汇报。
