# 下游核对

在用户已授权的核对范围内，以最终上游仓库状态为事实来源。只读核对不授权回流或清理。维护者编辑、squash 合并、替代修复或冲突解决后，原始提交分支不再权威。

## 识别最终上游行为

Fetch upstream 并取得最终 PR 状态。已合并 PR 记录 merge、squash 或 rebase 提交 SHA 并检查其完整补丁。已关闭 PR 在上游搜索满足行为契约的替代提交。

对比四项：

1. 原下游行为与测试；
2. 已提交的贡献分支；
3. 最终上游实现；
4. 当前下游分支。

## 核对结果

| 结果 | 行动 |
|---|---|
| 下游与最终上游行为等价 | 记录等价；不重复提交 |
| 上游改进了提交的修复 | 记录最终上游 delta；已授权回流时用 `downstream-sync` 移植 |
| 上游实现了替代修复 | 评估行为差异；已授权回流时移植所需行为 |
| PR 关闭且上游无修复 | 下游修复有效则保留；记录拒绝理由与剩余分歧 |
| 上游原生重写后下游含过时脚手架 | 报告清理候选；仅在已授权范围内处理 |

用补丁身份与行为对比决定修复是否已存在，而不是提交标题或作者。

## 验证

只读等价核对复用对应提交的已有验证；实际回流后按影响运行必要冷检查，不无故重复或扩大验证。确认有意保留下游的配置、调试、发布或兼容代码仍然必要。

最终报告必须说明对比了哪个上游 SHA、验证了哪个下游 SHA，以及是否按设计保留了任何 fork 专属差异。
