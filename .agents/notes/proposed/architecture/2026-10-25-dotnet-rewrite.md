# Agent Note: 以可独立验证的游戏流程推进 C# 与 .NET 重写

Status: proposed

## 问题

源码启动主界面会沿 UI 的导入关系初始化自动化和 OCR。开发入口的文件重载重启整个应用，部分规则测试也依赖 UI 或真实自动化模块，使局部修改的反馈成本过高。

游戏行为分布在任务入口、识别、输入、父子流程、配置和 UI 中。函数返回不一定表示任务完成；截图后的动作也可能使已有观察失效。编写者身份不能代替明确的状态所有权与游戏证据。AI 维护需要定位当前行为、真实场景和长期决策理由。

## 提案

### 目标与范围

应用及随包工具分阶段迁移到 C#、.NET 10 LTS、Avalonia 与 SukiUI。最终产品启动和运行不依赖 Python；资产提取、Agent Notes 检查等开发工具可以保留 Python。

重写以主界面启动、局部验证速度、游戏行为正确性和 AI 维护所需的明确契约为验收对象。用户已明确授权替换和精简旧逻辑，现阶段不要求向下兼容。资源、既有业务行为和真实场景提供证据；新实现可根据测量和观察采用更合适的算法、配置及接口。Python 与 .NET 入口并存期间使用隔离配置，实机上同一游戏窗口只由一个实例控制。

### 模块与依赖

| 项目 | 责任 |
| --- | --- |
| `AALC.Core` | 游戏状态、业务规则和有类型的流程决策；不依赖 UI 框架、视觉库或操作系统 |
| `AALC.Runtime` | 任务编排、取消、超时、重试、运行事件与配置；定义外部效果接口 |
| `AALC.Vision` | 模板匹配、OCR、地图识别和图像资源生命周期 |
| `AALC.Platform.Windows` | 窗口、进程、截图、输入、MuMu、ADB、OBS 与桌面分身接入 |
| `AALC.Desktop` | Avalonia 页面、ViewModel、主题、语言及组合入口 |
| `AALC.Cli` | 场景回放、视觉对照、诊断和性能测量入口 |

Runtime 引用 Core；具体设备与视觉实现依赖运行接口。Desktop 和 CLI 组装实际实现，Runtime 不引用具体后端。只有有外部效果或替换需求的边界引入接口。项目内部按日常、战斗、镜牢路线、商店、奖励等业务组织。

既有桌面分身宿主先保留独立进程及 IPC 协议，COM、STA 消息循环和音频控制单独验证；AAALC 的宿主与分身内进程边界见[分身边界决策](../../implemented/architecture/2026-10-31-aaalc-desktop-clone-boundaries.md)。更新器保持独立可执行入口，在发布迁移阶段处理。

### 桌面 UI

Avalonia 负责 XAML、布局、渲染与窗口，SukiUI 负责控件主题和导航。使用同一套主题资源表达文字、选择、焦点与禁用状态；状态同时有文字，不只靠颜色区分。任务、场景回放、设置使用稳定导航，游戏画面和运行记录各有固定区域。默认使用静态背景，并把主题加载计入启动测量。

现有 Windows 自动化和桌面分身依赖保持明确；UI 框架具备跨平台能力不扩大本项目支持范围。SukiUI 与 Avalonia 按兼容依赖固定版本，升级时核验控件与启动表现。

### 流程、观察和输入所有权

流程依次执行观察、决策、输入、重新观察、确认后继状态。发出动作后不得直接把预期界面当成事实。观察包含帧标识、时间、窗口尺寸和坐标变换；窗口或会话变化后丢弃旧坐标。

流程结果明确表达完成、交回父流程、失败和取消。未知识别保留为未知，不按成功或足够资源继续。日常批次数仍由任务层管理；镜牢队列沿用[活动队列决策](../../archived/architecture/2026-05-03-mirror-team-queue-normalization.md)。

每个游戏会话有一个运行状态所有者和输入执行者。配置持久化与当前任务状态分开；UI 观察运行状态并发送命令，不直接驱动设备。取消协作传播，输入执行前再次检查；释放已按下的键鼠属于收尾。原生调用超时不等于调用已经终止，资源和会话确认可用前禁止新任务接管。应用关闭保持最多 5 秒优雅等待。

### 启动和开发反馈

启动依次完成最小入口检查、主界面可交互、所选任务准备、任务执行。首屏不初始化 OCR、连接模拟器、同步请求网络、扫描全部资源或构造所有工具窗口。初始化并发有界，避免后台任务争抢首屏资源。

界面、离线场景、真实设备任务各有入口。普通规则测试不创建 桌面窗口、不初始化模型、不等待真实时间。CLI 与桌面端运行同一套流程代码。

视觉采用 OpenCvSharp 与官方 ONNX Runtime C# API。当前模板、模型、词典和真实帧构成可复现基线；算法、前后处理与资源可以按识别结果和性能改进。数值对照用于解释差异，验收核对游戏状态、动作位置及后继状态。图像与推理缓冲区有明确所有者、复用和释放时机。场景观察和局部控件反馈分别声明所需识别，避免每次截图重复执行整页 OCR。

发布先使用自包含目录包；ReadyToRun 是否启用由启动和体积实测决定。启动目标不依赖 裁剪或 NativeAOT。

### AI 所需的当前知识

- AGENTS 与 skills 保存修改规则和阅读入口。
- 架构说明保存模块责任和依赖。
- 流程说明保存入口、观察、动作、出口、接手者、重试、停止和证据范围。
- 场景记录保存截图、动作、期望与游戏版本、语言、分辨率、资源和模型身份。
- Agent Notes 保存长期理由及真实替代方案，遵循[既有笔记契约](../../README.md)。

源码事实、人工描述、真实画面与模拟场景分别标记。人工编写的场景不作为游戏实测证据。运行事件包含流程、步骤、帧、命中规则、动作和耗时，能够定位失败原因。

迁移一个功能时核验其资源语义和样本，不批量生成未经验证的游戏说明。流程行为以生产实现和已核验的场景为依据，长期理由只在相应 Note 维护。

### 迁移顺序

| 阶段 | 交付与出口 |
| --- | --- |
| 0 | 启动分段基线、现有功能与配置清单、关键流程证据及风险 |
| 1 | 最小 Avalonia 主界面、独立场景运行器、视觉对照；早期验证 OCR、MuMu、桌面分身的高风险接口 |
| 2 | 一个完整小流程，贯通 UI、配置、截图、输入、停止、事件和离线回放 |
| 3 | 日常入口、采光、编队、战斗结算、体力与模块、通行证等流程 |
| 4 | 镜牢入口、主题包、路线、战斗、事件、奖励、商店、结算与队伍轮转；完整卡包权重与罪人顺序编辑器 |
| 5 | 支持范围内的全部截图、输入、模拟器和桌面分身后端 |
| 6 | 剩余页面、资源管理、截图、问题回放、教程跳过、无限战斗、汉化工具、主题与翻译 |
| 7 | 构建、资源加工、更新器及失败恢复 |
| 8 | 独立包试运行，核对功能、性能与支持设备后切换默认入口 |

每个业务阶段同时交付对应界面与验证。设备早期验证解决可行性，完整接入阶段覆盖其全部契约。全程功能对照表中的项目须已迁移或有明确处理结论，不能按新实现的较小范围认定整体完成。

### 镜牢编辑器的交付顺序与数据归属

镜牢选人和主题权重编辑器属于阶段 4，已随运行主体提供；主桌面普通镜牢保留奖励模式已完成实机通关，领取模式与困难镜牢仍需验收。

星光、观测位置与页面信息层级遵循[已实施的界面设计原则](../../implemented/architecture/2026-10-27-aaalc-interface-design.md)；观测定位依据见[实际位移与选择确认](../../implemented/bug-fix/2026-10-27-observation-position-and-selection.md)。

主题包目录以稳定 ID 表达身份，中文、英文、OCR 别名和封面是目录属性。`MirrorThemeCatalog` 使用显式 C# 定义统一维护 87 个主题包，普通和困难默认权重分别定义。用户配置只保存队伍的 `NormalWeights`、`HardWeights` 覆盖，不复制目录，也不为语言分开保存。两种模式的覆盖独立；同步按钮显式复制两种模式都支持的包，保留困难专属项。这样修改识别别名或游戏译名时，无需同步改写用户偏好。队伍轮换只改变队伍对象顺序。未知包使用明确的未知权重，配置校验拒绝未定义 ID 和越界权重。

权重编辑器提供完整模式目录、封面与名称、搜索、优选阈值、重置默认、全部设为 -5、普通同步困难。显示名称与匹配别名分离；最长别名优先的匹配表在目录静态初始化时建立。窗口先编辑内存副本，应用后更新队伍草稿，主界面保存后写入独立 profile 的 `settings.json`。

罪人顺序继续使用不重复的 ID 数组。2×6 编辑器展示头像、姓名和派生顺序号，点击移除或追加，提供全选、前七人和清空；商店技能替换复用紧凑多选模式。前七位与后五位使用不同横幅与字色。十二个控件保持实例稳定，头像与覆盖图片不在每次选择时解码；使用原生圆角裁切及渲染缩放、透明度过渡，不动画布局尺寸。

权重窗口按需创建。按本轮明确要求，87 个卡包使用响应式 WrapPanel，分批加入控件，封面在后台限两路并发以显示尺寸解码，内存缓存跨窗口共享；角色图片在组件可见后才加载。应用首屏不读取这些图片。配置区与运行监控分开到标签页，保留完整编辑宽度。

验收记录编辑器首次加载、缓存后重开、搜索、连续选择及最小窗口，核对配置往返与多语言标题命中。交互预算为输入至可见反馈 P95 不超过 50ms，缓存后重开不超过 300ms，滚动与悬停按 60Hz 的 16.7ms 帧预算检查；首次图片解码和缓存命中分开报告。预算需在参考机器上实测，不把模型运算时间当作渲染帧耗时。

### 首个交付里程碑

首个里程碑贯通启动基线、Avalonia 主界面、独立场景运行器、视觉结果对照和邮件领取流程。

邮件领取依据[生产运行器](../../../../src/AALC.Runtime/Mail/MailRunner.cs)、[现有测试](../../../../tests/AALC.Core.Tests/MailTests.cs)及可获取的真实画面核验。覆盖进入邮箱、领取、奖励确认、空邮箱、关闭返回、取消与超时。人工场景必须明确标记来源，真实设备结果单独保存。流程验证必须观察动作后的状态，不按截图调用次数自动推进。

启动记录分开报告依赖恢复、完整编译、增量编译、进程启动、主界面可交互和模型准备。采用相同机器与可比配置，保留原始结果和测量条件。

视觉对照使用相同帧、模板、模型和参数；记录中间预处理、匹配分数与位置、推理输出及影响决策的差异。数值容差明确，不能把模板自匹配作为真实场景识别通过。

其余业务与发布迁移完成前，重写方案保持 proposed；实现说明和验证材料记录已具备的入口及其实际范围。

### 复用与配置

复用图片、字体、声音、ONNX 模型、词典、业务数据、翻译文案、已有 C# 宿主和 IPC。Python 的场景与期望改写为 C# 检查；Qt 布局、信号、样式和模型前后处理实现分别迁移。

新配置按业务意图定义字段，消费预算、编队选择和完成次数具有明确含义。旧配置可以作为用户偏好的读取来源；新程序写入独立配置，保留原配置和自定义资源。本阶段不增加旧字段、旧 API 或旧流程的兼容层。

发布保留[更新协议决策](../../archived/architecture/2026-05-05-updater-bootstrap-protocol.md)的受管文件所有权和保护路径原则。新产品的安装、更新与失败恢复按实际发行入口设计，现阶段不要求旧版原地升级或旧二进制互操作。

## 曾考虑的替代方案

- WPF 加手写控件样式：最小界面出现对比度和视觉一致性问题；选择 Avalonia 与 SukiUI 统一控件状态、导航和主题，承担额外渲染依赖与版本兼容的验证成本。

- 保持 Python 并优化导入、缓存和测试隔离：可以较小成本改善当前反馈速度；C# 重写同时追求显式类型契约、Windows 集成和产品运行时统一，因此作为分阶段迁移推进。
- 逐文件翻译 Python：容易保留导入时初始化、全局状态和隐式流程交接，采用完整业务功能迁移来核对行为。
- 一次替换整个应用：验证范围和配置恢复成本过高，采用隔离入口逐阶段交付。
- 把所有流程写成通用 YAML 状态机：需要额外语言和解释器，普通 C# 类型与局部流程已经能表达所需规则。
- 首先依赖 NativeAOT 或单文件打包解决启动：不能消除业务初始化工作，且引入 UI 与原生库兼容问题；先拆分初始化并测量常规目录发布。

## 验收标准

- 主界面可交互不依赖 OCR、设备或网络初始化。初始预算为新进程 P95 不超过 1.5 秒；结合参考机器基线校准并保留测量条件。
- 普通局部修改至针对性验证结果初始预算不超过 5 秒；单个纯规则场景执行不超过 1 秒，编译与执行分别记录。
- 启动至首个有效动作的总耗时同时报告，不以延后模型加载替代整体性能验证。
- 场景可由 CLI 独立运行，使用生产决策代码和虚拟时间；失败以非零退出码和可定位证据报告。
- 视觉对照覆盖代表性真实帧及边界样本，记录数值与行为差异；OCR 不能只检查模型是否可加载。
- 邮件领取有完整生产路径、动作后观察、成功与失败结果、取消和有界等待；离线、真实环境验证范围分别报告。
- 配置、截图、日志和自定义资源保留，验证使用隔离配置或副本；同一游戏会话不被新旧实例并发控制。
- 后续全量切换前，功能与后端对照、升级与回退的证据齐备。

## 风险

- 隐含游戏语义迁移错误会引起错误结算、重复消费或错误轮转。按调用者、动作、出口及接手者核验契约。
- OpenCV、OCR 的颜色、缩放、裁剪、文字顺序与后处理差异可能改变输入坐标。固定数据和版本作差分对照。
- DPI、原生缓冲区、COM 和模拟器版本差异需要真实设备验证；协作取消不能中断所有原生调用。
- 提前初始化或过度抽象可能重建当前启动和维护问题。首个里程碑先验证实际反馈速度。
- AI 生成的流程说明和场景可能互相印证同一个错误。保留证据来源与未知状态，真实画面独立核验。
- 与 Python 上游逐渐分离后，修复按业务契约和场景映射移植，不能继续依赖直接 cherry-pick。
- 更新失败与配置回退需要验证实际发行版本行为；用户资产保护优先于安装目录清理。
