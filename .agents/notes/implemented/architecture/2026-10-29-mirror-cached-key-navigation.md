# Agent Note: 用缓存路线的方向键继续镜牢导航

Status: implemented

## 问题

镜牢节点结束后会返回地图。每次执行已规划的下一步前重新识别局部地图，会重复等待地图稳定和运行节点识别，抵消路线缓存的速度收益。

## 决策

[MirrorRouteFlow](../../../../dotnet/src/AALC.Runtime/Mirror/MirrorRouteFlow.cs) 保存已确认的局部路线中相邻节点的类别与相对位移。地图可见且没有加载提示时，直接按位移选择方向键，再根据新画面确认选择和目的页；确认进入后才消费缓存。商店离开后也优先使用剩余路线。

换层时清除缓存；方向键没有选中反馈时清除缓存，并从当前地图重新识别与规划。缓存用尽时继续按[局部观测规则](2026-10-26-mirror-map-observations.md)扫描可见地图，规划首步仍需当前帧的节点与连线证据。导航沿用现有游戏窗口按键通道和协作式停止。

## 曾考虑的替代方案

每次返回地图先识别节点、连接和巴士，再核对缓存，可以发现更多路线变化，但每个缓存节点都要重复运行识别。当前方案在按键后检查选择与目的页，减少重复扫描。

## 后果

已规划的后续节点不再逐一重扫；由于单个局部视野可能看不到整层，缓存用尽后仍会再次扫描。按键确认可以发现未响应，但不能识别所有进入了错误分支的情况，游戏地图布局或按键规则变化时需要重新核验。
