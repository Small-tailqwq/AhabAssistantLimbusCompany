# Agent Note: AAALC 界面沿用游戏的空间关系与操作语义

Status: implemented

## 问题

玩家已经熟悉游戏里的增益位置、体系顺序和选择方式。将这些对象改写成通用数字表单，会把辨认对象的工作转嫁给玩家。重复的状态、空预览和说明文字也会增加阅读量，挤占配置空间。

## 决策

[主窗口](../../../../dotnet/src/AALC.Desktop/MainWindow.axaml)和编辑器遵循以下原则：

- 文字提供完成操作所需的信息。标题、控件标签和布局已经表达的内容不再配一段说明；副作用、备份位置和具体错误保留在对应操作处。
- 空闲页面以配置和操作为主。预览、日志和结果有内容才显示；结果卡片按内容占用高度。运行时保留一个跨页任务状态，局部结果直接展示具体内容。
- 游戏已经建立的空间关系和点击语义优先复用。[星光组件](../../../../dotnet/src/AALC.Desktop/StarBonusView.axaml)按两行五列排列，标题、`+`、`++` 分别对应三档；再次点击已选段会移除该段及其后续等级。效果放在悬停提示，成本由实际等级计算。
- 有限的合法组合由控件表达。初始饰品优先顺序直接选择六种排列，跳过商店楼层直接勾选，避免输入重复编号或自行记忆分隔格式。
- [观测编辑器](../../../../dotnet/src/AALC.Desktop/ObserveGiftEditorWindow.axaml)沿用游戏的体系图标顺序、III／II／I 等级和八列目录；点击位置加入或移除，右侧显示顺序和已选项。最多选择三件，第四次选择不会替换已有项。
- 图片、OCR 和独立编辑窗口按需创建。编辑窗口持有队伍草稿副本，应用才更新队伍，主页面保存才写入 profile；取消不修改队伍配置。

星光数据集中在 [MirrorStarBonusCatalog](../../../../dotnet/src/AALC.Core/Features/Mirror/MirrorStarBonusCatalog.cs)，供显示和入口成本计算共享。界面选择投影到既有配置字段，运行层继续独立校验，具体观测约束见[观测定位笔记](../bug-fix/2026-10-27-observation-position-and-selection.md)。本笔记补充[重写方案的桌面 UI 决策](../../proposed/architecture/2026-10-25-dotnet-rewrite.md)，不改变其余迁移阶段。

## 曾考虑的替代方案

通用数字框能快速覆盖配置字段，但会隐藏游戏对象之间的位置与前后依赖；星光和饰品顺序使用游戏对应的选择方式，普通次数和权重仍使用数字控件。

完整饰品名称与缩略图目录需要可靠的观测排序数据。现有资源没有完整目录，因此编辑器明确选择游戏中的位置，保留体系、等级、行和列，不生成未经核对的饰品名称或缩略图映射。

## 后果

玩家可以沿用游戏里的位置记忆，常用操作无需阅读配置格式。罪人头像和主题封面保留各自的识别信息，复杂选项通过折叠和独立窗口展开。

观测目录更新仍可能改变位置含义；位置选择界面不提供饰品身份随版本迁移的保证。获得可靠的当前目录后，名称与图片应关联同一位置来源，再增加身份映射。
