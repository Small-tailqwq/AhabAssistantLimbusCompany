# 体力、模块与通行证奖励

日常编排通过 `IGameSession` 取得关联帧的模板结果、文字与检测框，执行鼠标动作并发布进度。返回主页由 `DailyNavigation` 负责；本文件中的兑换和通行证流程不启动游戏或创建输入后端。

## 模块与狂气

`EnkephalinFlow.ConvertAsync(session, cancellationToken)` 检查体力兑换面板。可批量兑换时选择全部并确认，再从新截图确认按钮变为不可用或面板已经消失。默认已选一个模块时，最大值箭头可以灰态；流程要求确认按钮可用、数量 OCR 为 1、当前体力为 20～39，然后直接确认一次。该分支须在新帧观察到体力恰好减少 20 才报告完成；未观察到预期扣除时超时失败，不重复确认。体力不足且确认不可用属于正常无操作，关闭面板后返回成功。

按钮可用性沿用 Python PC 路径：`all_in` 模板阈值为 0.5，按钮区域平均 HSV 饱和度至少 15、亮度至少 65。资源来自现有 `enkephalin/` 目录；主页入口阈值为 0.75，面板打开动作间隔至少 1.2 秒。取消后需重新观察到面板消失才结束。

单模块的确认按钮使用独立亮度条件：模板命中区域的平均 HSV V 至少 120。实帧 `logs/dotnet_daily_debug/20261025-153856-131/frame-000006.png` 中，24 点体力、默认数量 1，最大值箭头平均 V 为 59.35，确认按钮为 184.48；同次运行第 48 帧兑换后的确认按钮平均 V 为 79.49。数量与当前体力分别在 1440 基准 `(1300,620,1440,700)`、`(1150,800,1380,930)` 区域放大两倍识别，当前体力读取分数线前的数字。

`EnkephalinFlow.RefillAsync(session, tier, grandet, cancellationToken)` 接收每日价格档位上限：

| 档位 | 允许的价格 |
|---|---|
| 0 | 跳过 |
| 1 | 26 |
| 2 | 26、52 |
| 3 | 26、52、78 |

档位不是本次额外购买次数。已经买过第一档、设置为第二档时，只再允许价格 52 的确认。流程先兑换现有体力，切换狂气面板，匹配价格并确认；每次确认后必须从新观察确认价格上升，才能继续判断下一档。价格模板覆盖 26/52/78，缺少模板时在价格区域 OCR 识别数字；104 表示已超出第三档。价格不变或无法识别时停止继续消费。退出后再次将体力转换成模块。

第三次确认后的真实价格帧为 `logs/dotnet_daily_debug/20261025-153856-131/frame-000042.png`。1440 基准价格区域 `(1130,510,1320,660)` 在 1280×720 下为 `(565,255,95,75)`，放大两倍识别。生产 CLI 在短行处理修改前后各运行三次，均返回 `104`、置信度 `0.99411`、原帧检测框 `(582,270,60,46)`；新进程含模型加载的耗时中位数为 491.83／515.27 ms。该区域高 75、宽高比小于 8，继续使用 DB 路径。记录为 `logs/dotnet_daily_debug/ocr-small-crops-20261025/before.json` 和 `after.json`。

Grandet 模式使用 `lunacy_assets` 锚点下方的倒计时，归一化 O/D 为 0 后解析 `mm:ss`，保留 Python 的 `minute >= 5 && seconds >= 20` 条件，秒字段须小于 60。单次等待上限为六分钟，支持取消；外层运行时限由日常编排设置。

## 通行证

`PassRewardFlow.RunAsync(session, missions, levels, seasonMissions, cancellationToken)` 领取每日／每周任务、可选赛季任务及等级奖励。`ClaimSeasonMissions` 是独立开关，默认关闭；任务奖励先于等级奖励执行。流程结束停留通行证页，由日常编排返回主页。

流程以已选中标签及分区红色提示判断是否需要领取，仅在有提示时识别进度；赛季任务提示消失后立即退出。等级奖励领取后确认奖励弹窗，待弹窗关闭、等级提示消失才报告完成。具体的原 AALC 调用链、领取前后画面、滚动边界与验证记录见[通行证领取](pass-rewards.md)。

## 原生页面 OCR

```csharp
using var reader = new PageTextReader(modelsDirectory);
IReadOnlyList<RecognizedText> text = reader.Read(pixelFrame, region, scale, cancellationToken);
```

构造函数不加载模型，首次识别时才加载以下实际文件名：

- `ch_PP-OCRv4_det_infer.onnx`
- `ch_PP-OCRv4_rec_infer.onnx`
- `ppocr_keys_v1.txt`，识别模型带字典 metadata 时优先使用 metadata。

模型目录由调用方指定，支持独立部署目录。生产路径不调用 Python。`RecognizedText.Bounds` 为全帧坐标，已还原 ROI 偏移和放大倍数。过程包含灰度、非二值图 CLAHE、DB 检测、检测框扩张、透视裁剪和 CTC 识别。ONNX 推理通过 `RunOptions.Terminate` 响应取消。

检测参数沿用现有 RapidOCR 配置：最短边至少 736、尺寸对齐 32、分割阈值 0.3、框分数阈值 0.5、2×2 膨胀、unclip 比例 1.6。C# 对检测得到的最小矩形按面积／周长距离直接扩张；Python 使用 pyclipper 的整数圆角偏移。两者的任意画面逐像素等价没有作为接口承诺。

页面读取逐框识别，不执行 180° 角度分类、批量宽度分组或单字框生成；竖长检测框按生产规则旋转 90°。验证范围为当前游戏的正向横排文字。既有 `recognize` 单裁剪入口保持原预处理与输出格式。

## OCR 性能

使用 `desktop-20261025-144332/profile/runs/20261025-144817-744` 中保存的第 1、3、21 帧离线测量全页 OCR，检测到的文字数分别为 25、30、84。每组运行三轮，排除第一轮，以下为其余六次的墙钟时间中位数：

| 阶段 | 连续缓冲区优化前 | 优化后 |
|---|---:|---:|
| 检测预处理 | 133.6 ms | 6.9 ms |
| 检测 ONNX 推理 | 82.6 ms | 83.4 ms |
| 检测后处理 | 98.3 ms | 3.7 ms |
| 识别预处理总计 | 34.5 ms | 38.0 ms |
| 识别 ONNX 推理总计 | 276.7 ms | 258.4 ms |
| CTC 解码总计 | 1256.0 ms | 6.4 ms |
| 全页 OCR | 1895.4 ms | 410.1 ms |

CTC 逐类别比较直接索引连续浮点缓冲区，保留比较顺序、相同分数时的首项选择及置信度舍入。检测输入直接写入连续 NCHW 缓冲区；输出概率整块复制到浮点 Mat，严格 `>0.3f` 二值化后继续原有膨胀和检测框处理。该组连续缓冲区优化测量使用相同的模型、检测参数、裁剪与识别规则；短行直识别及输入尺寸处理见[视觉接口](vision.md#小-roi-检查)。

同机默认 ORT 线程最快；限制为 1、2、4 个线程时，优化前全页中位数分别为 2594、2383、2158 ms，因此保留默认线程设置。

三张实机截图的三轮输出共九次，文字、置信度与框逐值一致；原五个文字裁剪的文本、CTC token、概率、置信度和输入尺寸也逐值一致。四张历史截图的 17 框及十行颜色判定重新与生产 Python 核对，结果与前述对照相同。

汇总记录在 `logs/dotnet_daily_debug/ocr-perf-final-20261025/summary.json`，详细输出在同目录及 `ocr-perf-20261025/`。测量通过临时源码探针完成，未启动游戏或重建 Desktop；系统缓存和后台负载未受控，数值用于说明该组截图上的耗时变化。
